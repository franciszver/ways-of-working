## Always

- **Verification gates "done".** Run the real thing after your final edit and quote the decisive output line. Check every requirement against actual output, not memory. Say exactly "I verified X (evidence)" / "I did not verify Y (reason)" — never imply an unchecked claim passed.
- **Ground every edit.** Read a file before editing it; re-read after a failed edit. Never use a function, import, flag, or config key not confirmed in this repo, its installed packages, or tool output — label the unconfirmable "unverified".
- **Complete code only.** Never write `...`, `// rest unchanged`, or TODO stubs into a real file. Match the surrounding style. After each substantive edit, run the cheapest real check: targeted test → build/typecheck → lint → execute.
- **Stay in scope.** Do what was asked; log tempting side-improvements and report them at the end instead of doing them. Don't gold-plate; don't stop at "superficially works" when production quality was implied.
- **Report honestly, outcome first.** Failures reported with their output, unsoftened. No filler, no narration of the journey. Stuck after three refuted hypotheses → say so with the current state; a truthful "stuck" beats a confident guess.

## Prose style (all text you write)

Apply the spirit of Simplified Technical English (ASD-STE100) to docs, commit messages, PR descriptions, reports, replies, and code comments — never to code, identifiers, quoted output, or proper nouns. One term per concept, one meaning per word. Instructions ≤20 words, active voice with a named actor ("Run the tests", not "The tests should be run"), plain verbs ("use" not "utilize"). One topic per paragraph, most important sentence first.

## Working process

Plan, implement, and review as separate passes; review every diff cold (fresh context) before it lands. The plan lives on a board (or `WORKPLAN.md`): one issue = one branch = one PR, conventional commits, red-first tests (the failing case committed before the fix). Three gates before merge: simplify → security review → code review, every finding fixed and the suite re-run green. Log owner decisions the session they are made in `prd/DECISIONS.md`.

## Session continuity

If `HANDOFF.md` exists at the repo root, read it first and verify its two cheapest claims before starting. When ending a session mid-task, write one: goal, numbered requirements with status and evidence, exact next action, decisions with reasons, gotchas, verbatim commands.
